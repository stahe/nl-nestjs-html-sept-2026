    4. De view en het bijbehorende model

    Tot nu toe genereerden acties hun eigen antwoorden. In een MVC-applicatie is dat de rol van een view: een bestand dat de HTML-pagina beschrijft, met plaatshouders voor de gegevens die de actie eraan doorgeeft: het model van de view. We gebruiken de view-engine [Handlebars] via het pakket [hbs], dat haar aanpast aan [Express].

    import { NestFactory } from '@nestjs/core';
import { NestExpressApplication } from '@nestjs/platform-express';
import { join } from 'path';
import { AppModule } from './app.module';

async function bootstrap() {
  // NestExpressApplication: geeft toegang tot de Express-specifieke methoden
  const app = await NestFactory.create<NestExpressApplication>(AppModule);
  // de views staan in de map [views], in de root van het project;
  // na compilatie staat dit bestand in dist/: de root is dus '..'
  app.setBaseViewsDir(join(__dirname, '..', 'views'));
  // de view-engine: Handlebars, geleverd door het pakket [hbs]
  app.setViewEngine('hbs');
  await app.listen(3000);
  console.log('Server started on http://localhost:3000');
}

    import { Controller, Get, Param, Render, Res } from '@nestjs/common';
import { Response } from 'express';

@Controller()
export class ViewsController {
  // @Render('index'): het door de actie geretourneerde object is het MODEL van de view
  // views/index.hbs; NestJS roept zelf de view-engine aan
  @Get()
  @Render('index')
  home(): object {
    return {
      title: 'My first view',
      message: 'This page was built by Handlebars, on the server.',
      time: new Date().toLocaleTimeString('en-US'),
    };
  }

  // res.render(view, model): de view wordt gekozen TIJDENS de uitvoering van de actie
  @Get('hello/:name')
  hello(@Param('name') name: string, @Res() res: Response): void {
    if (name === 'unknown') {
      res.status(404).render('unknown', { name });
      return;
    }
    res.render('index', {
      title: `Hello ${name}`,
      message: 'This time, the view was chosen by res.render.',
      time: new Date().toLocaleTimeString('en-US'),
    });
  }
}
    • regel 8–9: [@Render('index')] verwijst naar de view [views/index.hbs]. Het object dat de actie teruggeeft, is niet langer het antwoord; het is het model van de view;
    • regel 11–15: het model: drie waarden, [title], [message] en [time];
    • regel 19–30: als de view afhangt van het verzoek, gebruikt de actie [res.render(view, model)] van het antwoord van [Express] (geïnjecteerd door [@Res()]; zie Voorbeeld 05). Hier toont de naam [unknown] een andere view, met statuscode 404.

    We lichten deze code toe:

    • Regel 9: [{{!-- ... --}}] is een commentaar ([Handlebars]): het verschijnt niet op de gegenereerde pagina (in tegenstelling tot een HTML-commentaar zoals [<!-- -->]);
    • regel 10: een variabele die in het model ontbreekt ([nonexistent]) levert een lege tekenreeks op, zonder foutmelding;
    • regel 12–13: [{{html}}] escapet de speciale tekens van HTML ([<] wordt [&lt;]...): de tekst wordt ongewijzigd weergegeven. [{{{html}}}] (drie accolades) wordt zonder escaping ingevoegd: het wordt als HTML geïnterpreteerd. Drie accolades gebruikt u alleen voor HTML die door de applicatie is gegenereerd, nooit voor gegevens die een gebruiker heeft ingevoerd: een gebruiker zou HTML of zelfs [JavaScript] in de pagina kunnen injecteren (een zogeheten [XSS]-aanval);
    • regel 15–19: [{{#if}}] / [{{else}}] / [{{/if}}]: een voorwaardelijk blok. De voorwaarde is een waarde uit het model, geen expressie: [false], [undefined], [null], [''], [0] en de lege array gelden als onwaar;
    • regel 20–22: [{{#unless}}] is het omgekeerde van [{{#if}}];
    • Regel 26–32: [{{#each}}] herhaalt de inhoud ervan voor elk element van een array. Binnen het blok is de context het huidige element: [{{name}}] is de naam van het huidige product. Er zijn speciale variabelen beschikbaar: [@index] (positie, beginnend bij 0), [@first] en [@last]. [../currency] verwijst naar de bovenliggende context, [@root.name] naar het hoofdmodel;
    • regel 36: een [{{else}}] binnen een [{{#each}}] behandelt het geval van een lege array;
    • Regel 39–41: [{{#with}}] wijzigt de context; ook een relatief pad is mogelijk (regel 42).

    import { NestFactory } from '@nestjs/core';
import { NestExpressApplication } from '@nestjs/platform-express';
import { NextFunction, Request, Response } from 'express';
import * as hbs from 'hbs';
import { dirname, join } from 'path';
import { AppModule } from './app.module';

const ROOT = join(__dirname, '..');

async function bootstrap() {
  const app = await NestFactory.create<NestExpressApplication>(AppModule);

  // 1. statische bestanden: public/css/styles.css wordt geserveerd als /css/styles.css
  app.useStaticAssets(join(ROOT, 'public'));
  // Bootstrap wordt rechtstreeks vanuit node_modules geserveerd, onder /bootstrap/
  app.useStaticAssets(join(dirname(require.resolve('bootstrap/package.json')), 'dist'), { prefix: '/bootstrap/' });

  // 2. de views; views/layout.hbs wordt de layout van ALLE pagina's
  app.setBaseViewsDir(join(ROOT, 'views'));
  app.setViewEngine('hbs');
  // 3. de partials: views/partials/xxx.hbs wordt ingevoegd met {{> xxx}}
  await new Promise<void>((done) => hbs.registerPartials(join(ROOT, 'views', 'partials'), () => done()));

  // 4. een Express-middleware: wat die in res.locals zet, wordt
  //    toegevoegd aan het model van ELKE view
  app.use((req: Request, res: Response, next: NextFunction) => {
    res.locals.path = req.path;
    res.locals.year = new Date().getFullYear();
    next();
  });

  await app.listen(3000);
  console.log('Server started on http://localhost:3000');
}

bootstrap();

    • regel 16: het CSS-framework [Bootstrap] wordt rechtstreeks vanuit de map [node_modules] geserveerd, onder het voorvoegsel [/bootstrap/]. [require.resolve] zoekt de pakketmap van [bootstrap] op, waar die ook is geïnstalleerd (hier in [examples/node_modules]);

[registerPartials] leest de map asynchroon: we wachten tot dat klaar is (de functie die als tweede argument is doorgegeven, wordt aan het einde aangeroepen) voordat we de server starten;

    import { HelperOptions } from 'handlebars';

// de module 'hbs' heeft geen typedeclaraties: we beschrijven wat we ervan gebruiken
interface Hbs {
  registerHelper(name: string, fn: (...args: any[]) => unknown): void;
  handlebars: { SafeString: new (html: string) => unknown; escapeExpression(text: string): string };
}

export function registerHelpers(hbs: Hbs): void {
  // {{uppercase name}}: een eenvoudige helper, één argument
  hbs.registerHelper('uppercase', (text: unknown) => String(text ?? '').toUpperCase());

  // {{#if (eq a b)}}: gebruikt als subexpressie, tussen haakjes
  hbs.registerHelper('eq', (a: unknown, b: unknown) => a === b);

  // {{active path '/products'}}: "active" als de huidige pagina onder dit pad valt
  hbs.registerHelper('active', (path: unknown, prefix: unknown) =>
    typeof path === 'string' && typeof prefix === 'string' && path.startsWith(prefix) ? 'active' : '',
  );

  // {{money amount currency='USD'}}: het LAATSTE argument van een helper is altijd
  // het Handlebars-object [options]; options.hash bevat de benoemde
  // parameters, options.data.root het volledige model van de pagina (inclusief res.locals)
  hbs.registerHelper('money', (amount: unknown, options: HelperOptions) => {
    const currency = options.hash.currency ?? 'EUR';
    const language = options.data?.root?.lang ?? 'en-US';
    return new Intl.NumberFormat(language, { style: 'currency', currency: currency }).format(Number(amount));
  });

  // {{date when}}: een datum in de notatie van de taal van de pagina
  hbs.registerHelper('date', (when: unknown, options: HelperOptions) => {
    const language = options.data?.root?.lang ?? 'en-US';
    return new Intl.DateTimeFormat(language, { dateStyle: 'full' }).format(new Date(String(when)));
  });

  // {{badge stock}}: een helper die HTML opbouwt. SafeString geeft
  // Handlebars aan de uitvoer NIET te escapen; de helper moet dan zelf
  // de gegevens die hij erin invoegt escapen (escapeExpression)
  hbs.registerHelper('badge', (stock: unknown) => {
    const n = Number(stock);
    const cssClass = n > 0 ? 'text-bg-success' : 'text-bg-danger';
    const text = hbs.handlebars.escapeExpression(n > 0 ? `${n} in stock` : 'sold out');
    return new hbs.handlebars.SafeString(`<span class="badge ${cssClass}">${text}</span>`);
  });
}

      comment: text(body.comment),

      country: text(body.country),
      languages: array(body.languages),
      birthDate: text(body.birthDate),
      token: text(body.token),
    };

  // het model van de view: de lijsten, waarbij elke optie als aangevinkt
  // / geselecteerd wordt gemarkeerd naargelang de invoer
  private model(input: Input, received: object | null): object {
    return {
      input,
      titles: this.lists.titles.map((t) => ({ value: t, checked: t === input.title })),
      hobbies: this.lists.hobbies.map((h) => ({ value: h, checked: input.hobbies.includes(h) })),
      countries: this.lists.countries.map((c) => ({ ...c, selected: c.code === input.country })),
      languages: this.lists.languages.map((l) => ({ value: l, selected: input.languages.includes(l) })),
      received: received ? JSON.stringify(received, null, 2) : null,
    };
  }
}

// een ontbrekend veld (niet-aangevinkt selectievakje...) wordt helemaal niet verzonden
function text(value: unknown): string {
  return typeof value === 'string' ? value : '';
}

// één aangevinkte waarde: "sport"; twee: ["sport", "music"]; geen: undefined
function array(value: unknown): string[] {
  if (value === undefined) return [];
  return Array.isArray(value) ? value : [String(value)];
}

export type Errors = Record<string, string>;

export async function validateForm<T extends object>(
  cls: ClassConstructor<T>,
  body: Record<string, unknown>,
): Promise<{ dto: T; errors: Errors }> {
  // 1. ontvangen object -> instantie van de klasse (@Transform / @Type worden toegepast)
  const dto = plainToInstance(cls, body);
  // 2. controle van alle beperkingen
  const violations = await validate(dto);
  // 3. we bewaren de eerste melding van elk ongeldig veld
  const errors: Errors = {};
  for (const v of violations) {
    errors[v.property] = Object.values(v.constraints ?? {})[0];
  }
  return { dto, errors };
}

    4.7.1. Validatie door de browser

    4.8. Voorbeeld 20: het patroon Post/Redirect/Get

    Wanneer een POST-formulier succesvol wordt verzonden, kan de actie rechtstreeks een pagina tonen. Het probleem ontstaat als de gebruiker die pagina vervolgens ververst (toets F5): de browser verzendt het formulier opnieuw en de bewerking wordt een tweede keer uitgevoerd (een bestelling die twee keer wordt geplaatst, een afspraak die twee keer wordt gemaakt...). Het patroon Post / Redirect / Get (PRG) voorkomt dit probleem: een geslaagde POST-actie genereert geen pagina, maar leidt om naar een GET-pagina. Het opnieuw laden van die pagina verstuurt alleen het GET-verzoek, dat geen effect heeft.

    Eén detail resteert: de GET-pagina moet een bericht tonen (“de taak is toegevoegd”), hoewel dat bericht door de POST-actie in een ander verzoek is gegenereerd. Het wordt doorgegeven in een kortlevende cookie, die door het volgende verzoek wordt gelezen en verwijderd: dit is een flashbericht.

    import { NextFunction, Request, Response } from 'express';

const FLASH_COOKIE = 'flash';

// bewaart een melding die door de VOLGENDE pagina wordt getoond, en slechts één keer
export function flash(res: Response, message: string): void {
  res.cookie(FLASH_COOKIE, message, { httpOnly: true, sameSite: 'lax', maxAge: 60_000 });
}

// bij elk verzoek: de openstaande melding gaat van de cookie naar res.locals (dus
// naar het model van de view), en de cookie wordt gewist
export function flashMiddleware(req: Request, res: Response, next: NextFunction): void {
  res.locals.flash = req.cookies?.[FLASH_COOKIE] ?? null;
  if (res.locals.flash) {
    res.clearCookie(FLASH_COOKIE);
  }
  next();
}

    // bevestiging van de formulieren met het attribuut data-confirmation="..."
// Zonder JavaScript worden deze formulieren gewoon zonder bevestiging verzonden.
(() => {
  const modal = document.getElementById('confirmation-modal');
  const message = document.getElementById('confirmation-modal-message');
  let pending = null; // het formulier dat moet worden verzonden als de gebruiker bevestigt

  // 1. we onderscheppen het verzenden van de te bevestigen formulieren
  document.querySelectorAll('form[data-confirmation]').forEach((form) => {
    form.addEventListener('submit', (event) => {
      event.preventDefault(); // het verzenden wordt uitgesteld
      pending = form;
      message.textContent = form.dataset.confirmation;
      modal.classList.remove('d-none'); // het venster verschijnt
    });
  });

  // 2. de twee knoppen van het venster
  modal.addEventListener('click', (event) => {
    const action = event.target.dataset.action;
    if (action === 'yes') {
      pending.submit(); // verzenden, ZONDER de gebeurtenis 'submit' opnieuw af te vuren
    } else if (action === 'no') {
      modal.classList.add('d-none');
      pending = null;
    }
  });
})();
    • Regel 3: de code is verpakt in een functie die onmiddellijk wordt uitgevoerd, om globale variabelen te vermijden;
    • regels 9–16: het verzenden van elk formulier met het attribuut [data-confirmation] wordt onderschept. [preventDefault()] schort het verzenden op; het formulier wordt bewaard, de vraag wordt in het venster geplaatst ([textContent], niet [innerHTML]: de vraag wordt als tekst weergegeven en nooit als HTML geïnterpreteerd) en het venster wordt getoond;
    • Regels 19–27: „Ja” verzendt het bewaarde formulier. De methode [submit()] van een formulier verzendt het zonder de gebeurtenis [submit] te activeren: er verschijnt dus geen nieuwe bevestigingsvraag. „Nee” verbergt het venster.

Dit is het principe van geleidelijke verbetering: [JavaScript] voegt gemak toe, maar is niet essentieel.
