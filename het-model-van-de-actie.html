    3. Het model van de actie

    Een actie heeft informatie nodig die de browser verstuurt: de parameters van de URL ([?name=martin&age=42]), de velden van een formulier en de routeparameters. In de oorspronkelijke cursus wordt al deze informatie het model van de actie genoemd. Dit hoofdstuk laat zien hoe [NestJS] het aan de actie levert, het omzet naar het juiste type en het valideert.

    import { Controller, DefaultValuePipe, Get, ParseIntPipe, Query } from '@nestjs/common';

@Controller('parameters')
export class ParametersController {
  // /parameters/action01?name=martin
  @Get('action01')
  action01(@Query('name') name: string): string {
    return `name = [${name}], of type ${typeof name}`;
  }

  // /parameters/action02?age=42: een parameter is ALTIJD een string
  @Get('action02')
  action02(@Query('age') age: number): string {
    return `age = [${age}], of type ${typeof age}`;
  }

  // /parameters/action03?age=42: ParseIntPipe converteert (of weigert)
  @Get('action03')
  action03(@Query('age', ParseIntPipe) age: number): string {
    return `age = [${age}], of type ${typeof age}`;
  }

  // /parameters/action04?page=2: een standaardwaarde als de parameter ontbreekt
  @Get('action04')
  action04(@Query('page', new DefaultValuePipe(1), ParseIntPipe) page: number): string {
    return `page = [${page}], of type ${typeof page}`;
  }

  // /parameters/action05?name=martin&age=42: alle parameters tegelijk
  @Get('action05')
  action05(@Query() parameters: Record<string, string>): object {
    return parameters;
  }
}

    We lichten deze code toe:

    • Regel 6–9: [@Query('name')] injecteert de waarde van de parameter [name] uit de URL (het deel na [?], de zogeheten querystring of [query string]);
    • regel 12–15: de parameter [age] is gedeclareerd met het type [number]... maar dit type is slechts een [TypeScript]-declaratie die tijdens het compileren wordt verwijderd. Wat we ontvangen is altijd een tekenreeks, zoals de uitvoering laat zien;
    • regel 18–21: [ParseIntPipe] is een pipe: een object dat de waarde van een parameter omzet (en valideert) voordat die de actie bereikt. Hier wordt de tekenreeks ['42'] het getal 42; een niet-numerieke tekenreeks veroorzaakt een 400-fout (Bad Request), zonder dat de actie wordt uitgevoerd;
    • regel 24–27: de pipes worden aan elkaar geschakeld: [DefaultValuePipe(1)] vervangt een ontbrekende parameter door 1, waarna [ParseIntPipe] hem omzet;
    • regel 30–33: [@Query()], zonder argumenten, injecteert een object met alle parameters van de URL.

    3.2. Voorbeeld 08: een model van de actie, beschreven door een klasse

    Als een actie meerdere parameters heeft, worden ze beschreven door een klasse, vaak een [DTO] ([Data Transfer Object]) genoemd. Elk veld van de klasse heeft validatiedecorators uit de bibliotheek [class-validator]. Deze zijn gelijkwaardig aan de attributen [[Required]], [[Range]]enzovoort van [ASP.NET MVC].

    import { Type } from 'class-transformer';
import { IsEmail, IsIn, IsInt, IsNotEmpty, IsOptional, Length, Max, Min } from 'class-validator';

export class PersonDto {
  @IsNotEmpty({ message: 'the name is required' })
  @Length(2, 20, { message: 'the name must have 2 to 20 characters' })
  name: string;

  @Type(() => Number)
  @IsInt({ message: 'the age must be an integer' })
  @Min(0, { message: 'the age must be positive' })
  @Max(150, { message: 'the age cannot exceed 150' })
  age: number;

  @IsIn(['Mr', 'Mme', 'Melle'], { message: 'unknown title' })
  title: string;

  @IsOptional()
  @IsEmail({}, { message: 'invalid email address' })
  email?: string;
}

    We lichten deze code toe:

    • regel 1: [@Type] komt uit de bibliotheek [class-transformer], die de ontvangen gegevens omzet;
    • regel 2: de validatiedecorators van [class-validator];
    • regel 5–7: de naam is verplicht ([@IsNotEmpty]) en moet tussen 2 en 20 tekens lang zijn ([@Length]). Elke decorator accepteert een eigen foutmelding;
    • regel 9–13: [@Type(() => Number)] vereist dat de ontvangen tekenreeks vóór de validatie wordt omgezet in een getal: een geheel getal ([@IsInt]) tussen 0 en 150 ([@Min], [@Max]);
    • regel 15–16: de titel moet een van de waarden in een lijst zijn;
    • regel 18–20: het e-mailadres is optioneel ([@IsOptional]); als het aanwezig is, moet het geldig zijn ([@IsEmail]).

import { PersonDto } from './person.dto';

@Controller('persons')
export class PersonsController {
  // /persons/action01?name=martin&age=42&title=Mr

    import { NestFactory } from '@nestjs/core';
import { ValidationPipe } from '@nestjs/common';
import { AppModule } from './app.module';

async function bootstrap() {
  const app = await NestFactory.create(AppModule);
  // automatische validatie van ALLE actiemodellen die door een klasse zijn beschreven
  app.useGlobalPipes(
    new ValidationPipe({
      transform: true, // converteert de ontvangen strings naar de gedeclareerde typen
      whitelist: true, // verwijdert de velden die niet in de klasse zijn gedeclareerd
    }),
  );
  await app.listen(3000);
  console.log('Server started on http://localhost:3000');
}

    • regel 11: [whitelist: true]: parameters die met geen enkel veld van de klasse overeenkomen, worden verwijderd.

    import { Controller, Get, Query } from '@nestjs/common';
import { plainToInstance } from 'class-transformer';
import { validate } from 'class-validator';
import { PersonDto } from './person.dto';

@Controller('persons')
export class PersonsController {
  // hier geen ValidationPipe: de actie ontvangt de ONBEWERKTE parameters en
  // beslist zelf wat er met de fouten gebeurt
  @Get('action01')
  async action01(@Query() raw: Record<string, string>): Promise<string> {
    // 1. onbewerkt object -> PersonDto-instantie (inclusief @Type-conversies)
    const person = plainToInstance(PersonDto, raw);
    // 2. controle van de beperkingen (@IsNotEmpty, @Min...)
    const errors = await validate(person);
    // 3. in beide gevallen een HTML-pagina: geen 400-fout
    if (errors.length === 0) {
      return `<p>Welcome ${person.title} ${person.name} (${person.age} years old)</p>`;
    }
    const items = errors
      .map((e) => `<li>${e.property}: ${Object.values(e.constraints ?? {}).join(', ')}</li>`)
      .join('');
    return `<p>The form contains errors:</p><ul>${items}</ul>`;
  }
}

    We lichten deze code toe:

    • regel 11: de actie ontvangt de onbewerkte parameters: een object waarvan alle velden tekenreeksen zijn;
    • regel 13: [plainToInstance] ([class-transformer]) maakt een instantie van [PersonDto] aan op basis van het onbewerkte object en past daarbij de omzettingen toe ([@Type]);
    • regel 15: [validate] ([class-validator]) controleert alle beperkingen. Het geeft een array met fouten terug, die leeg is als alles in orde is. Elke fout geeft het problematische veld aan ([property]) en de meldingen van de geschonden beperkingen ([constraints]);
    • regel 17–18: geen fouten: een welkomstpagina;
    • regel 20–23: anders een pagina met de lijst van fouten. In beide gevallen is het antwoord een HTML-pagina, met statuscode 200.

    Dit is de techniek die alle formulieren in de casus gebruiken (zie Voorbeeld 19).

    import { Controller, Get, Query } from '@nestjs/common';
import { ChoiceDto } from './choice.dto';

@Controller('arrays')
export class ArraysController {
  // /arrays/action01?color=red&color=green: wat Express ontvangt

  action01(@Query('color') color: string | string[]): object {

    import { Transform } from 'class-transformer';
import { ArrayMinSize, IsArray, IsIn } from 'class-validator';

export class ChoiceDto {
  // ?color=red -> "red"; ?color=red&color=green -> ["red","green"]
  // @Transform maakt in beide gevallen een array

    import { BadRequestException, Injectable, PipeTransform } from '@nestjs/common';

// zet een Franse datum "23/09/2026" om in een ISO-datum "2026-09-23"
@Injectable()
export class DateFrPipe implements PipeTransform<string, string> {
  transform(value: string): string {
    const m = /^(\d{2})\/(\d{2})\/(\d{4})$/.exec(value ?? '');
    if (!m) {
      throw new BadRequestException(`[${value}] is not a date in the dd/mm/yyyy format`);
    }
    const [, day, month, year] = m;
    const iso = `${year}-${month}-${day}`;
    // "31/02/2026" heeft de juiste vorm, maar bestaat niet
    if (new Date(`${iso}T00:00:00Z`).toISOString().slice(0, 10) !== iso) {
      throw new BadRequestException(`the date [${value}] does not exist`);
    }
    return iso;
  }
}
    • regel 4–5: een pipe is een klasse met [@Injectable()] die de interface [PipeTransform<input, output>] implementeert;
    • regel 6: de methode [transform] ontvangt de waarde van de parameter en geeft de omgezette waarde terug, die de actie zal ontvangen;
    • regel 7–9: een waarde die niet de vorm [dd/mm/yyyy] heeft, veroorzaakt een [BadRequestException] (400);
    • regel 13–15: een datum die het juiste formaat heeft maar niet bestaat (31/02/2026) wordt ook afgewezen: [new Date] “corrigeert” die naar 03/03/2026, wat wordt gedetecteerd.

    import { createParamDecorator, ExecutionContext } from '@nestjs/common';
import { Request } from 'express';

// @Language(): de voorkeurstaal van de browser, gelezen uit de header
// "Accept-Language: fr-FR,fr;q=0.9,en;q=0.8" -> "fr"
export const Language = createParamDecorator((fallback: string | undefined, ctx: ExecutionContext): string => {
  const req = ctx.switchToHttp().getRequest<Request>();
  const header = req.get('accept-language') ?? '';
  const first = header.split(',')[0].trim().slice(0, 2).toLowerCase();
  return first || fallback || 'fr';
});
    • Regel 6: [createParamDecorator] maakt een parameterdecorator aan, vergelijkbaar met [@Query] of [@Body]. De functie ontvangt het argument van de decorator ([@Language('fr')]) en de uitvoeringscontext van het verzoek;
    • regel 7: de context geeft toegang tot het verzoek van [Express];
    • regel 8–10: de eerste twee letters van de header [Accept-Language] worden teruggegeven; die header geeft de voorkeurstalen van de gebruiker aan.

async function bootstrap() {
  const app = await NestFactory.create(AppModule);
  app.useGlobalPipes(
    new ValidationPipe({

    3.6.4. Conclusie

    Het model van de actie wordt door [NestJS] samengesteld op basis van het verzoek: routeparameters ([@Param]), URL ([@Query]), de body ([@Body]) en headers ([@Headers]). De pipes zetten deze waarden om en valideren ze. Bij een HTML-applicatie is het meestal beter om het model zelf te valideren (Voorbeeld 09), zodat u het formulier opnieuw kunt tonen. Dat is het onderwerp van het volgende hoofdstuk.
