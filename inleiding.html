    1.1. De rol van NestJS in een webapplicatie

    Een webapplicatie wordt vaak opgebouwd uit lagen, waarbij elke laag alleen met de naburige lagen communiceert:

    • de weblaag ontvangt HTTP-verzoeken van de browser en stuurt er HTML-pagina’s naar terug. [NestJS] helpt ons bij het schrijven van deze laag;
    • de bedrijfslaag bevat de bedrijfsregels van de applicatie (bijvoorbeeld “een patiënt kan maar één toekomstige afspraak hebben”). Ze weet niets van het web: ze zou net zo goed een opdrachtregelapplicatie kunnen bedienen;
    • de laag voor gegevenstoegang (de [DAO]-laag, van [Data Access Object]) leest uit en schrijft naar de database. We gebruiken de ORM [TypeORM] ([Object Relational Mapper]), die de rijen van de tabellen koppelt aan [TypeScript]-objecten.

    De weblaag zelf volgt het [MVC] ([Model – View – Controller])-model:

    • de controller (C) is een klasse waarvan de methoden, ook wel acties genoemd, elk een bepaald type verzoek afhandelen (bijvoorbeeld [GET /schedule]). Een actie leest de parameters van het verzoek, roept de bedrijfslaag aan en kiest vervolgens de view die moet worden weergegeven;
    • het model (M) is de verzameling gegevens die de actie aan de view doorgeeft: een eenvoudig [JavaScript]-object;
    • de view (V) is een [Handlebars]-bestand (extensie [.hbs]): een HTML-bestand waarin [{{...}}]-tags worden vervangen door gegevens uit het model.

    De verwerking van een verzoek volgt de genummerde stappen in het diagram:

    • 1: de browser stuurt een HTTP-verzoek, bijvoorbeeld [GET /schedule?doctorId=1&day=2026-09-24];
    • 2: [NestJS], dat gebruikmaakt van de webserver [Express], kiest de actie die dit verzoek moet afhandelen: dit is de routing. Voordat het verzoek daar aankomt, kan het langs middleware, guards, interceptors en pipes gaan, die we in de volgende hoofdstukken bespreken;
    • 3: de actie vraagt de gegevens die ze nodig heeft op bij de bedrijfslaag;
    • 4: ze bouwt het model voor de view en geeft aan welke view het moet weergeven;
    • 5: de view-engine [Handlebars] genereert de HTML-pagina, die [NestJS] naar de browser terugstuurt.

    [NestJS] is een framework voor [Node.js], geschreven in [TypeScript]. Het bouwt voort op de concepten van de frameworks [Spring] ([Java]) en [Angular] : decorators ([@Controller], [@Get], [@Injectable]...) beschrijven de rol van elke klasse, en dependency injection voorziet elk object van de afhankelijkheden die het nodig heeft. Het wordt vaak gebruikt om servers te schrijven die JSON teruggeven aan een [JavaScript]-client ([Angular], [React], [Flutter]...). Dit document gebruikt het om een klassieke webapplicatie te schrijven: de server genereert de HTML-pagina’s en de browser geeft ze alleen weer.

    1.2. Gebruikte tools

    De voorbeelden zijn geschreven en getest met de volgende tools (de installatie ervan wordt beschreven in de bijlage):

    • [Node.js] 20 en de bijbehorende pakketbeheerder [npm];
    • de editor [Visual Studio Code];
    • een recente browser ([Chrome], [Firefox], [Edge]);
    • het opdrachtregelprogramma [curl], dat onbewerkte HTTP-antwoorden toont (het is opgenomen in [Windows] 10 en 11);
    • het DBMS [MySQL] (of [MariaDB]), bijvoorbeeld dat van [Laragon] onder [Windows], vanaf het hoofdstuk over gegevenstoegang.

    De bibliotheekversies zijn die in het bestand [package.json] in de map met voorbeelden: [NestJS] 10, [TypeScript] 5, [hbs] 4 ([Handlebars]), [class-validator] 0.14, [TypeORM] 0.3, [Bootstrap] 5.

    Open om een voorbeeld uit te voeren een console in de map

    en typ:

    npx nest start

    [npx] zoekt het programma [nest] in de map [node_modules] van de bovenliggende map. [nest start] compileert de [TypeScript]-code naar de map [dist] en voert vervolgens [dist/main.js] uit. Met de optie [--watch] wordt de code opnieuw gecompileerd en de server opnieuw gestart zodra een [.ts]-bestand wordt gewijzigd:

    npx nest start --watch

    Alle voorbeelden luisteren op poort 3000: er kan er dus maar één tegelijk draaien. Stop de server met [Ctrl-C] in de console.

    We lichten dit bestand toe:

    • regel 3: de gecompileerde code gebruikt de modules [CommonJS] van [Node.js] ([require]);
    • regel 4: de gegenereerde code is recente [JavaScript] (ES2022), die wordt ondersteund door [Node.js] 20;
    • regel 6–7: de broncode staat in [src] en de gecompileerde code in [dist];
    • regel 9–10: vereist voor [NestJS]. Decorators ([@Controller]...) zijn een functie van [TypeScript] die moet worden ingeschakeld, en [emitDecoratorMetadata] bewaart de typen van de parameters van constructors en methoden in de gecompileerde code: hierdoor weet [NestJS] welk object in een constructor moet worden geïnjecteerd;
    • regel 12: de compiler meldt het gebruik van een waarde die mogelijk [null] of [undefined] is;
    • regel 13: declaratiebestanden van bibliotheken worden niet gecontroleerd (snellere compilatie).
