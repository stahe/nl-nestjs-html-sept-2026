    6. Gegevensscopes

    Een webapplicatie bedient veel gebruikers tegelijk, en elke gebruiker doet talrijke verzoeken. Gegevens kunnen daarom op drie niveaus worden gedeeld, de zogeheten scope:

    • applicatiescope: de gegevens worden door alle gebruikers gedeeld gedurende de hele levensduur van de server (bijvoorbeeld de lijst met artsen);
    • requestscope: de gegevens bestaan alleen tijdens de duur van één verzoek (het model van een view);
    • clientscope: de gegevens zijn specifiek voor één gebruiker en moeten van het ene verzoek naar het volgende bewaard blijven (de gekozen taal, de ingelogde gebruiker).

    De oorspronkelijke cursus gebruikte voor deze laatste scope de [ASP.NET]-sessie: een opslagruimte aan de serverkant die uniek is voor elke browser. Dit document doet, net als de casus, zonder sessie: gegevens met clientscope worden door de browser in cookies bewaard. De server slaat tussen twee verzoeken van dezelfde gebruiker niets op: hij heet stateless ([stateless]). Dat maakt het bijvoorbeeld mogelijk om meerdere identieke servers achter een load balancer te draaien. De keerzijde: een cookie staat onder controle van de gebruiker, die hem kan lezen en wijzigen. In hoofdstuk 8 ziet u hoe een ondertekend token het mogelijk maakt de cookie toch te vertrouwen.

    import { Injectable } from '@nestjs/common';

// APPLICATION-scope (de standaard): één enkele instantie, bij het opstarten aangemaakt en
// gedeeld door ALLE verzoeken van ALLE gebruikers
@Injectable()
export class CounterService {
  private total = 0;

  increment(): number {
    return ++this.total;
  }
}

    Regels 5–6: een [NestJS]-service is standaard een singleton: één enkele instantie, bij het opstarten aangemaakt en gedeeld door alle verzoeken. Het veld [total] ervan heeft dus applicatiescope.

    import { Injectable, Scope } from '@nestjs/common';

let createdInstances = 0;

// REQUEST-scope: een NIEUWE instantie voor elk HTTP-verzoek
@Injectable({ scope: Scope.REQUEST })
export class RequestService {
  readonly number = ++createdInstances;
}

    Regel 6: de optie [scope: Scope.REQUEST] vraagt om een nieuwe instantie per verzoek. Het nummer van de instantie laat dit zien. Deze optie wordt zelden gebruikt: ze kost iets (er worden bij elk verzoek objecten aangemaakt) en ze plant zich voort: een controller die afhankelijk is van een service met requestscope krijgt zelf ook requestscope. [res.locals] is meestal voldoende.

    import { Controller, Get, Req, Res } from '@nestjs/common';
import { Request, Response } from 'express';
import { CounterService } from './counter.service';
import { RequestService } from './request.service';

@Controller()
export class ScopesController {
  constructor(
    private readonly counter: CounterService,
    private readonly request: RequestService,
  ) {}

  @Get()
  scopes(@Req() req: Request, @Res() res: Response): void {
    // CLIENT-scope: een gegeven dat door de BROWSER wordt bewaard (cookie)
    // en bij elk verzoek naar de server wordt teruggestuurd
    const myVisits = Number(req.cookies?.myVisits ?? 0) + 1;
    res.cookie('myVisits', String(myVisits), { httpOnly: true, sameSite: 'lax' });
    res.render('scopes', {
      total: this.counter.increment(),
      instance: this.request.number,
      myVisits,
    });
  }
}
    • regels 8–11: beide services worden geïnjecteerd;
    • regels 17–18: de clientscope: een teller die in een cookie is opgeslagen. De browser stuurt die bij elk verzoek terug; de actie verhoogt de teller en slaat hem weer op;
    • regels 19–23: de drie waarden worden aan de view doorgegeven.

    import { NestFactory } from '@nestjs/core';
import { NestExpressApplication } from '@nestjs/platform-express';
import * as cookieParser from 'cookie-parser';
import { NextFunction, Request, Response } from 'express';
import { dirname, join } from 'path';
import { AppModule } from './app.module';

async function bootstrap() {
  const app = await NestFactory.create<NestExpressApplication>(AppModule);
  app.useStaticAssets(join(dirname(require.resolve('bootstrap/package.json')), 'dist'), { prefix: '/bootstrap/' });
  app.setBaseViewsDir(join(__dirname, '..', 'views'));
  app.setViewEngine('hbs');
  app.use(cookieParser());
  // REQUEST-scope: res.locals ontstaat en verdwijnt met het verzoek
  app.use((req: Request, res: Response, next: NextFunction) => {
    res.locals.start = new Date().toISOString().slice(11, 23);
    next();
  });
  await app.listen(3000);
  console.log('Server started on http://localhost:3000');
}

bootstrap();

    regels 15–18: de requestscope met [res.locals]: het tijdstip waarop het verzoek is ontvangen.
