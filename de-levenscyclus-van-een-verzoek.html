    7. De levenscyclus van een verzoek

    Tussen de komst van een verzoek en de uitvoering van de actie zijn in [NestJS] meerdere soorten objecten betrokken, elk met een eigen rol. Sommige daarvan hebben we al ontmoet: middleware ([res.locals], [cookie-parser]) en pipes ([ParseIntPipe], [ValidationPipe]). De casus gebruikt ze alle vijf:

    Object
    Rol
    In de casus
    middleware
    bereidt het verzoek voor; kent de actie nog niet
    cookies lezen, taal, flashbericht
    guard
    geeft toegang tot de actie of weigert die
    authenticatie (JWT), rollen
    interceptor
    code vóór en na de actie
    de ingelogde gebruiker, beschikbaar gesteld aan views
    pipe
    zet een parameter om en valideert die
    [ParseIntPipe]
    exception filter
    zet een exception om in een respons
    HTML-foutpagina's, doorverwijzing naar /login

    import { Injectable, NestMiddleware } from '@nestjs/common';
import { NextFunction, Request, Response } from 'express';

// 1. de MIDDLEWARE: de eerste die het verzoek ziet. Die weet nog niet
//    welke actie het zal afhandelen
@Injectable()
export class LoggerMiddleware implements NestMiddleware {
  use(req: Request, res: Response, next: NextFunction): void {
    console.log(`\n--- ${req.method} ${req.originalUrl}`);
    console.log('1. middleware');
    next(); // we dragen over aan de rest van de keten
  }
}
    • Regel 7: een [NestJS]-middleware is een klasse die [NestMiddleware] implementeert. Een eenvoudige functie, zoals in de vorige voorbeelden, zou ook werken;
    • Regel 11: de middleware moet [next()] aanroepen om de controle door te geven aan de volgende stap (of zelf een respons te sturen). Anders blijft het verzoek geblokkeerd.

    import { MiddlewareConsumer, Module, NestModule } from '@nestjs/common';
import { CalcController } from './calc.controller';

@Module({
  controllers: [CalcController],
})
export class AppModule implements NestModule {
  // een klassemiddleware wordt in de module geregistreerd
  configure(consumer: MiddlewareConsumer): void {
    consumer.apply(LoggerMiddleware).forRoutes('*');
  }
}

    import { CanActivate, ExecutionContext, Injectable } from '@nestjs/common';
import { Request } from 'express';

// 2. de GUARD: beslist of het verzoek de actie mag bereiken.
//    false -> NestJS gooit een ForbiddenException (403)
@Injectable()
export class BlockGuard implements CanActivate {
  canActivate(context: ExecutionContext): boolean {
    const req = context.switchToHttp().getRequest<Request>();
    // de guard kent de beoogde actie (wat de middleware niet deed)
    console.log(`2. guard (targeted action: ${context.getHandler().name})`);
    return req.query.block !== '1';
  }
}
    • regel 7: een guard implementeert [CanActivate];
    • regel 8: de methode [canActivate] ontvangt de uitvoeringscontext en geeft [true] terug (het verzoek gaat door) of [false] ([NestJS] genereert dan een [ForbiddenException], code 403);
    • regel 11: anders dan de middleware kent de guard de doelactie ([getHandler()]) en de bijbehorende controller ([getClass()]). Hierdoor kan een guard de decorators lezen die op de actie zijn toegepast (zie [@Roles], volgend hoofdstuk).

    import { CallHandler, ExecutionContext, Injectable, NestInterceptor } from '@nestjs/common';
import { Observable, tap } from 'rxjs';

// 3. de INTERCEPTOR: code VÓÓR de actie en NA de actie
@Injectable()
export class TimingInterceptor implements NestInterceptor {
  intercept(context: ExecutionContext, next: CallHandler): Observable<unknown> {
    console.log('3. interceptor (before)');
    const start = Date.now();
    // next.handle() voert uit wat volgt: pipes en dan de actie. Het resultaat
    // van de actie komt aan in de geretourneerde stroom (Observable)
    return next.handle().pipe(tap(() => console.log(`6. interceptor (after, ${Date.now() - start} ms)`)));
  }
}
    • regel 6: een interceptor implementeert [NestInterceptor];
    • regel 8: de code vóór [next.handle()] wordt vóór de actie uitgevoerd;
    • regel 12: [next.handle()] voert de rest uit (pipes gevolgd door de actie) en geeft een [RxJS] -stream ([Observable]) terug die het resultaat van de actie zal opleveren. De operator [tap] voert code uit na de actie, zonder het resultaat te wijzigen (met de operator [map] zou het wél gewijzigd kunnen worden).

    import { BadRequestException, Injectable, PipeTransform } from '@nestjs/common';

// 4. de PIPE: converteert en valideert een parameter van de actie
@Injectable()
export class IntegerPipe implements PipeTransform<string, number> {
  transform(value: string): number {
    console.log(`4. pipe (received value: "${value}")`);
    const n = Number(value);
    if (!Number.isInteger(n)) {
      throw new BadRequestException(`"${value}" is not an integer`);
    }
    return n;
  }
}

    Een pipe die lijkt op [ParseIntPipe] (zie voorbeeld 12).

    import { ArgumentsHost, Catch, ExceptionFilter, HttpException, HttpStatus } from '@nestjs/common';
import { Response } from 'express';

// x. de EXCEPTION FILTER: ontvangt elke onafgehandelde exception, waar
//    die ook vandaan komt (guard, pipe, actie...), en bouwt het antwoord op.
//    @Catch() zonder argument: alle exceptions
@Catch()
export class ErrorPageFilter implements ExceptionFilter {
  catch(exception: unknown, host: ArgumentsHost): void {
    const res = host.switchToHttp().getResponse<Response>();
    const status = exception instanceof HttpException ? exception.getStatus() : HttpStatus.INTERNAL_SERVER_ERROR;
    const message = exception instanceof HttpException ? exception.message : 'Internal error';
    console.log(`x. exception filter (${status}: ${message})`);
    // een HTML-pagina in plaats van het standaard JSON-antwoord van NestJS
    res.status(status).render('error', { status, message });
  }
}
    • Regel 7: [@Catch()] zonder argument: het filter ontvangt alle exceptions. [@Catch(HttpException)] zou het beperken tot de HTTP-exceptions;
    • Regel 9: de methode [catch] ontvangt de exception en een [host]-object dat toegang geeft tot het verzoek en de respons;
    • Regel 11: een [HttpException] bevat zijn statuscode. Elke andere exception (een programmeerfout, een onbereikbare database) leidt tot een 500-fout;
    • regel 15: in plaats van de standaard-JSON toont het filter een HTML-pagina met de juiste statuscode.

    import { NestFactory } from '@nestjs/core';
import { NestExpressApplication } from '@nestjs/platform-express';
import { dirname, join } from 'path';
import { AppModule } from './app.module';
import { TimingInterceptor } from './timing.interceptor';
import { ErrorPageFilter } from './error-page.filter';

async function bootstrap() {
  const app = await NestFactory.create<NestExpressApplication>(AppModule, { logger: ['error', 'warn'] });
  app.useStaticAssets(join(dirname(require.resolve('bootstrap/package.json')), 'dist'), { prefix: '/bootstrap/' });
  app.setBaseViewsDir(join(__dirname, '..', 'views'));
  app.setViewEngine('hbs');
  // een GLOBALE interceptor en filter: ze gelden voor alle routes
  app.useGlobalInterceptors(new TimingInterceptor());
  app.useGlobalFilters(new ErrorPageFilter());
  await app.listen(3000);
  console.log('Server started on http://localhost:3000');
}

bootstrap();

    • regels 14–15: de interceptor en het filter zijn globaal; ze gelden voor alle acties.

    import { Controller, Get, Param, Render, UseGuards } from '@nestjs/common';
import { BlockGuard } from './block.guard';
import { IntegerPipe } from './integer.pipe';

@Controller('square')
@UseGuards(BlockGuard) // de guard geldt voor alle acties van de controller
export class CalcController {
  @Get(':n')
  @Render('square')
  square(@Param('n', IntegerPipe) n: number): object {
    console.log(`5. action square(${n})`);
    if (n === 13) {
      throw new Error('13 brings bad luck'); // een "onverwachte" fout
    }
    return { n, square: n * n };
  }
}
    • regel 6: [@UseGuards] past een guard toe op alle acties van de controller (dat kan ook op één enkele actie);
    • regel 10: de pipe zet de parameter om;
    • regels 12–14: een „onverwachte” fout, om het filter in actie te zien.

    Dit logboek laat zien:

    • de volgorde van de stappen: middleware, guard, interceptor (vóór), pipe, actie, interceptor (na);
